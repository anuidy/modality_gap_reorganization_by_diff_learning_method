# 多模型M0基线执行改动日志

## 1. 改动类型

- 数据：将既有 COCO 5K 与 LCS 10K 固定 probe 输入 VISTA、ALBEF、BEiT-3 的 M0 推理流程。
- 模型：按 VISTA Stage-1、ALBEF 14M pretrain、BEiT-3 base-itc 的锁定 checkpoint 顺序执行单模型推理。
- 脚本：使用 `scripts/evaluation/extract_m0.py` 与 `scripts/evaluation/compute_six_metrics.py`。
- 配置：复用各模型 M0 config、固定 manifest、artifact contract 与六指标协议。

## 2. 改动位置

- 输入：`data/splits/` 下的 COCO/LCS manifest。
- 输出：`outputs/embeddings/m0/` 与 `outputs/metrics/m0/` 下对应模型目录。
- 执行入口：`scripts/evaluation/extract_m0.py`、`scripts/evaluation/compute_six_metrics.py`、`scripts/evaluation/validate_m0_outputs.py`。

## 3. 改动逻辑

每个模型依次完成 COCO artifact、LCS artifact、COCO 六指标和 LCS 六指标。所有导出均保存 raw pre-L2 `Z_I/Z_T`；指标在模型内部比较 image/text 表征，并复用固定 score-gap 与 geometry 协议。模型不并行运行，避免争用本机 GPU。

## 4. 改动效果

执行完成。VISTA Stage-1、ALBEF 14M pretrain、BEiT-3 base-itc 均生成 COCO 5K 与 LCS 10K artifact、六指标 JSON 和 M0 geometry reference；连同已有 CLIP，共验证 8 个 model-probe 输出：

- sample ID 顺序与各自 manifest 一致。
- shape 分别为 VISTA `[N, 768]`、ALBEF `[N, 256]`、BEiT-3 `[N, 768]`，stored dtype 均为 float32。
- 所有 embedding 与 metric 数值有限，无 NaN/Inf。
- 每个 score gap 包含全部 `N(N-1)` 非配对 semantic candidate。
- 每个 model-probe 都保存 1,000,000 个固定 upper-triangle pair 与 kNN@10 M0 reference。

本次未启动 Standard、Count-Matched Mixed、Full GCL 或任何正式训练。
